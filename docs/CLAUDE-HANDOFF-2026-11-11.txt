4. Virtual Storage RF2 ทำงานจริงแล้ว
- เจ้าของกดสร้าง virtualstorage ด้วยตนเอง: requested6703GiB, UI filesystem~6701GB
- Data replica2ชุด (คนละ compute), DRBD Protocol C, diskless Arbiter ช่วย quorum
- หลังทดสอบล่าสุด replicas UpToDate ทั้งคู่; NFS export active ฝั่ง Node2
- ทั้งคู่ mount NFS 172.16.12.106:/srv/gateway-exports/virtualstorage
  ที่ /mnt/ibhics/virtualstorage; เป็นพื้นที่ร่วมชุดเดียว ไม่บวกความจุซ้ำ
- UI เลือก Data/SSD cache/Do not use เอง; ไม่มี Mirror/Combine ให้สับสน
  RF2 aggregate policy: raw14904 -> หลัง RF27452 -> reserve10%745.2
  -> metadata/service3.25 -> ปัดลง6703GiB; SSD cache ไม่นับเป็น data capacity
  ใช้ความจุฝั่งเล็กกว่าถ้าไม่เท่ากัน; reserve10% ไม่ใช่การรับประกัน auto rebuild
- แก้ cache chunk hardcode ที่ทำ lvconvert fail: คำนวณจากขนาด cacheจริง
  และแก้ signature เก่าภายใน LV ที่ทำ lvcreate รอ prompt
- กู้ failed create แบบตรวจ serial/recorded operation ไม่ replay physical wipe อัตโนมัติ
- เลือก Writeback/Writethrough ได้และ applyทั้งคู่; ปัจจุบันเจ้าของเปิด Writeback
  เปลี่ยนกลับจะ flush dirty ก่อน ไม่ detach/discard cache เพื่อทำให้เร็ว
- Writeback มีความเสี่ยงต่อ pending data หาก SSD เสีย/ไฟดับ; RF2 ไม่แทน PLP/backup
- ย้าย thin_tmeta1GiB ไป SSD ทั้งสองเครื่องแบบ online แล้ว ไม่หยุด guest
  Node1 /dev/sdc(217481), Node2 /dev/sdd(217481), UUIDเดิมคงอยู่
- creator สำหรับ storageใหม่ยังจัด thin metadata บน HDD ต้องแก้แยกต่างหาก
- ผล microtest mean4.255->3.643ms, p9515.611->3.946ms เป็นตัวอย่างสั้น
  ไม่ใช่หลักฐาน Windows install เร็วขึ้นเท่านั้นหรือ throughputสูงสุด

5. Deploy VM / Template
- Full clone ลอง filesystem FICLONE ก่อนสำหรับ qcow2ที่เข้าเงื่อนไข
  เป็นไฟล์ independent ไม่มี backing dependency: ลบ template แล้ว cloneไม่พัง
- ไม่มี backing/internal snapshots, capacityตรงกัน; ถ้า filesystemไม่รองรับใช้ qemu-imgเดิม
  Storage I/O error ไม่กลบเป็น fallback; tempfile+fsync+atomic replace
- ทดสอบ synthetic แก้ cloneไม่กระทบต้นทางและลบต้นทางยังอ่าน cloneได้
- ดิสก์ Windows templateจริง120GiB virtual/~10.77GiB allocated clone0.0708s
  วัดเฉพาะ disk clone ไม่รวมสร้าง VM/customization/boot Windows
- ห้ามอ้างว่าเป็น linked clone หรือเร่งได้ทุก backend

7. Migration vstore3.8 — สำเร็จจริง
- ต้นเหตุแรก missing /etc/pki/CA/cacert.pem: ทั้งคู่ไม่มี TLS PKI/listener
- ทำ private keys/CSRs ในเครื่องแต่ละเครื่อง, CA private key อยู่ Node1เท่านั้น
  แลกเฉพาะ public CSRs/certs ไม่ส่ง private keys มา Mac หรือเข้า Git
- แยก cert/key ของ libvirt RPC กับ native QEMU migration, SAN hostname+IP,
  EKU serverAuth+clientAuth, peer verification เปิด, ไม่ใช้ no_verify
- TLS libvirtd bind managementIP:16514, allowed DN เฉพาะ compute control certs
  QEMU migrate_tls_force=1 และ migrate_tls_x509_verify=1
- helper installer/maintenance/migration_tls.py มี create-ca/prepare/sign/apply/activate
  เป็นขั้นตอน explicit/manual ยังไม่ใช่ auto enrollment เมื่อ Add node
- แก้ permission /etc/pki parentเป็น755 เพื่อให้ QEMUอ่าน public CAได้
  private directories/keys ยังจำกัดสิทธิ์
- เรียง stop/start socket+libvirtdให้ถูกและตรวจ QEMU PIDคงเดิม ไม่หยุด VM
- sourceเพิ่ม VIR_MIGRATE_TLS และ TLS_DESTINATION สำหรับ live qemu+tls
