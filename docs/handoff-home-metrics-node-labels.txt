Implementation
- CPU/memory allocation counts non-stopped VMs. CPU denominator is hardware
  threads, matching the existing dashboard. Percentages are not capped at 100.
- Disk allocation counts all regular VMs AND templates, including stopped VMs;
  stopped disks still reserve storage. The disk card explicitly labels this.
- Overallocated cards show the full percentage, a red border/value, an alert
  icon and the excess percentage. Unknown capacity displays a dash, never NaN.
- Actual CPU, memory and storage have SVG area/line charts, a current-use bar,
  used/available (CPU: idle) legend and resource-specific explanations. Decorative
  rings have been removed. Allocated resources have no bars, rings or charts.
  Values are sampled by the existing 10-second Home refresh, up to 60 samples /
  10 minutes in browser memory. No historical backend data is invented. Reloading
  starts a new history; missing measurements and gaps over 25 seconds break lines.
  All three charts use identical fixed 0/25/50/75/100% vertical axes and the same
  10-minute horizontal window (10 min ago / 5 min ago / Now). Hover timestamps
  remain available. A first-reading message explains when history is collecting.
- Memory measurements use reporting nodes' capacity, and partial reports are
  labelled. Existing Home per-node fallback bars are otherwise unchanged.
- PATCH /api/v1/cluster/nodes/{stable_name} accepts {"display_name": "..."}.
  This route is ADMIN ONLY and uses the existing audit middleware.
- Labels are trimmed, limited to 80 characters, reject Unicode control characters,
  allow Thai, and can be reset with an empty string. HTML is escaped in the UI.
- Cluster JSON has a new optional display_names mapping keyed by Node ID. Local,
  remote and witness labels persist; legacy cluster JSON loads without migration.
  Failed persistence restores the old label in memory.
- No membership key, Linux hostname, agent identity, VM node reference, backup
  reference or task reference is renamed. Same-label names may coexist; selectors
  show the stable ID beside a differing label to distinguish them.
- Edit labels in Nodes > Rename or Node > Settings > Node display name. Home,
  Nodes, breadcrumbs, VM detail/node column, storage and common node pickers use
  the label while keeping original IDs as values and URLs.

Deployment procedure (home2 installer; retained for reference)
1. Review the branch/diff and the preview images before installation.
2. Copy the final wheel and installer/install-home-metrics.sh to the server.
3. Run as root on the development server:
   bash install-home-metrics.sh ./ibhics-1.3.0b2+home2-py3-none-any.whl
   The installer checks installed version 1.3.0b2+home1, backs up the entire venv,
   restarts only ibhics-manager, verifies /api/v1/health and restores the backup
   automatically if installation or the health check fails. No VM power commands
   are issued. Manager restart invalidates browser sessions.
   Override IBHICS_DEPLOY_HEALTH_URL if the manager does not listen on localhost.
4. Sign in again. Check Home, Node Settings, Nodes and VM/backup references.
   The admin label test was performed and reset; no new permanent name was chosen.
