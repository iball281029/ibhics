NEW IMPLEMENTATION:
- Storage card: Prepare storage, Create Virtual Storage, per-node disk role selection,
  mirrored/combined local data layout, optional SSD cache, logical capacity and VIP.
- No disks preselected. Protected OS/VM/container disks cannot be selected.
- Review lists exact disk paths + serials + pools to erase. Checkbox + exact pool name
  confirmation, one-time 10-minute server receipt bound to current inventory fingerprint.
- Fresh node-side validation before releasing any pool. Shared RAID/LVM PV dependencies
  require complete selection; unknown mounts, system VGs, VM live/persistent/snapshot/
  qcow2 backing chains and container images protect their disks.
- Local provisioning uses md RAID1 when multiple mirrored data disks are chosen, LVM thin
  pool and optional LVM writethrough SSD cache. New managed VGs use ibhv-<name>.
- Disk audit and pool XML are retained. A failed destructive job is never silently replayed
  or rolled back by deleting partially created data.
- Durable manager/agent jobs keep progress across logout/refresh. Interrupted jobs require
  inspection. A single file lock serializes storage creation on each side.
- LINSTOR creates two data replicas and a diskless third vote on Arbiter; DRBD Reactor and
  LINSTOR Gateway provide one active NFS server and the storage VIP.
- Gateway REST API restricts NFS clients to the two data node IPv4 addresses (/32).
- Both libvirt nodes mount the same NFS export; it becomes a selectable VM/template pool.
- REST POST acknowledgement is not readiness: wait for Started/primary before mounting.
  Background replication is displayed as Synchronizing, not falsely labelled Healthy.
- Current kernel NFS implementation supports ONE Virtual Storage resource per cluster.
- The existing manager/control plane is on Node1; this does not implement VM restart HA,
  evacuation orchestration, distributed management or a controller HA deployment.
